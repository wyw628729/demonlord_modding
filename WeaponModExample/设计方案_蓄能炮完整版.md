# 蓄能炮完整版实现方案

## 需求

**武器特性：**
- 攻击视野 3，蓄力上限 2，激光宽度 1
- 开火持续 2 回合，每回合射出伤害 4、射程 4 的激光
- 魔王半径 2 格内有敌人时自动收炮背于身后，进入近战模式（可防反史莱姆）

**蓄力与开火状态切换：**
- 距敌 3 格时按前进对应键蓄力 1 层并进入蓄力状态
- 蓄力状态下再按前进键或 E 键则不移动蓄力 1 层
- 蓄力状态不可移动只能改变方向
- 开火状态可移动和改变方向
- 蓄力状态下侧向转向：同时蓄力 1 层。距离满蓄差 1 层时，按侧向键会转向并同时完成蓄力并直接开火
- 开火状态可侧方位移来保持瞄准方向不变的同时边位移边开火射第二段
- 闪避/弹反——蓄力 1 层，可累积至满蓄。满蓄后下次弹反、按 E 键、或距敌 3 格时按对应方向前进键均为不移动正常开火

**取消开火：**
- 开火状态按当前朝向的反方向键为取消剩余激光段数并后退

## 可行性结论：✅ 100% 优雅实现

### 关键发现：`isCharging` + `PlayerActionOver()` 机制

分析原版 `Skill_Weapon_Sword` 和 `Skill_Weapon_Laser` 的源码后发现，游戏内已有一个专为「蓄力控制输入」设计的字段：

```csharp
// UnitObjectPlayer.cs
public bool isCharging = false;
```

**`isCharging = true` 的效果（在 `PlayerInputCheck()` 中）：**
- **跳过** 门/宝箱检测（`PlayerCheckDoor`）
- **直接** 把方向键输入派发给 `OnInputDir`（即 Skill.Execute），技能完全接管输入

因此 `isCharging` 不是"锁定移动"，而是"把所有输入交给技能处理"。  
技能自己决定这一帧该移动、蓄力还是开火 —— **不移动只需不调用 `PlayerMove()`，调用 `PlayerActionOver()` 结束回合即可。**

### 各功能实现原理

| 功能 | 实现方式 | 参考来源 |
|------|----------|---------|
| **蓄力时阻止移动** | `p.isCharging = true` + `p.PlayerActionOver()` | `Skill_Weapon_Sword` |
| **蓄力时改变朝向** | 直接设 `p.aimDir` + `p.ChangeSpriteRotate()` | Sword 侧向转向 |
| **多段开火（2 回合）** | `isCharging = true` 保持接管，`firingRoundsLeft` 字段计数 | 技能实例跨回合持久 |
| **侧方位移不改变瞄准** | `p.MoveToPos(moveDir, ...)` + 回调中恢复 `p.aimDir = fireAimDir` | `Skill_Weapon_Laser` 后坐力模式 |
| **反向键取消后退** | 检测 `dir == -fireAimDir` → `p.PlayerMove(-fireAimDir, ...)` | 同 Laser |
| **E 键蓄力** | `IWeaponHooks.OnTrySkipButton()` 返回 `true` 拦截 | 现有钩子 |
| **弹反/闪避蓄力** | `IWeaponHooks.OnDodgeOrParry()` | 现有钩子 |
| **近战自动切换** | Execute 入口检测 `enemyObjects` 曼哈顿距离 | BattleObject.enemyObjects |
| **蓄力减伤** | `isCharging = true` 时游戏内置 30% 减伤，无需额外代码 | UnitObjectPlayer.Hurt() |

## 技能实例生命周期 — 为什么字段可以跨回合

`skillFactory: () => new Skill_Weapon_ChargeCannon()` 在 Mod 装备时 **只创建一次实例**，该实例随武器装备周期存活。

因此 `mode`、`chargeCount`、`firingRoundsLeft`、`fireAimDir` 等字段都是自然持久的 —— **无需写入 `weaponParams`**。

## 核心代码片段

### isCharging 接管机制（原版游戏源码）

```csharp
// UnitObjectPlayer.PlayerInputCheck()（游戏源码）
void PlayerInputCheck()
{
    if (isCharging)
    {
        // isCharging=true 时跳过门/箱检测，直接派发给技能
        OnInputDir?.Invoke(this);  // → Skill.Execute()
        return;
    }
    PlayerCheckDoor();  // 正常流程：检测门/箱
    // ...
}
```

### 蓄力不移动

```csharp
private void DoCharge(Vector2Int chargeDir)
{
    chargeCount++;
    p.SetSprite("charging1" + WeaponId);
    p.listenDelay += 0.25f;

    if (chargeCount >= GetChargeMax())
        TriggerFire();      // 满蓄 → 开火
    else
        p.PlayerActionOver(); // 蓄力中：结束回合但不移动，保持 isCharging
}
```

### 侧方位移保持瞄准

```csharp
private void SideMove(Vector2Int moveDir)
{
    var savedAimDir = fireAimDir; // 开火时锁定的方向
    p.MoveToPos(moveDir, 1, 1f, default, "move", "no", 0, () =>
    {
        // 位移完成后恢复开炮方向（原版 Laser 的后坐力也是这个模式）
        p.aimDir = savedAimDir;
        p.ChangeSpriteRotate(savedAimDir.x < 0);
        ShootOnce(savedAimDir);
    });
}
```

### 蓄力减伤（内置，零代码）

```csharp
// UnitObjectPlayer.Hurt()（游戏源码）
if (isCharging && BattleObject.Instance.chargingDefense)
    reallyDamage = (int)(0.3f * reallyDamage);
```

蓄力/开火状态下 `isCharging = true`，游戏自动应用 30% 受伤系数，无需额外编码。

## 结论

所有功能均可**优雅实现**，无需任何 Hack，无需临时 Buff 技能，无需延时恢复：

- `isCharging = true` 就是框架为蓄力类武器设计的接管机制（大剑已用此机制）
- Skill 实例跨回合持久，字段即状态
- `MoveToPos` 回调模式覆盖侧方位移+方向恢复（激光已用此模式）
